# Анализ анимации спинера перед статусами Working/Thinking

Дата анализа: 2026-08-18

## Итог

Да, сделать анимированный спинер можно без изменения протокола статусов, событий runtime и текстовых значений `Working...`, `Thinking...` и других рабочих состояний.

Текущий спинер не анимирован: иконка `fa5s.spinner` из QtAwesome сразу преобразуется в статичный `QPixmap`, после чего устанавливается в `QLabel`.

Наиболее подходящий вариант для этого проекта — использовать встроенную анимацию QtAwesome `qta.Spin` и управлять ею при переходе статусной системы в состояние `busy` и обратно.

## Что найдено в проекте

### Источник статусных переходов

Статусы передаются через событие `status_changed`:

- `ui/streaming.py` формирует события со статусами;
- `ui/window_components/main_window.py` принимает событие и передаёт его контроллеру;
- `ui/main_window_state.py`, класс `RunStatusController`, обрабатывает переходы состояний.

Основные переходы:

- запуск выполнения: `Working...`, `busy=True`;
- промежуточные состояния: например, `Thinking...`, `busy=True` для рабочих узлов;
- ожидание подтверждения или выбора пользователя: `busy=False`;
- завершение: `Ready`, `success=True`;
- ошибка: `Run failed`, `error=True`.

### Текущая отрисовка

В `ui/window_components/status_bar_manager.py` метод `set_status_visual()` выбирает иконку:

- `fa5s.spinner` для `busy=True`;
- `fa5s.check-circle` для успешного завершения;
- `fa5s.times-circle` для ошибки;
- `fa5s.circle` для обычного состояния.

Затем иконка создаётся через `_fa_icon()` и преобразуется в изображение:

```python
self.window.status_icon.setPixmap(_fa_icon(icon_name, color=color, size=14).pixmap(14, 14))
```

Именно преобразование в `QPixmap` делает спинер статичным. В текущем вызове не создаётся объект анимации и не запускается таймер вращения.

Статусная иконка и текст создаются в `ui/window_components/menu_builder.py` как `QLabel`. Это позволяет заменить статичный `setPixmap()` на управляемый анимированный icon/widget без изменения формата статусных событий.

## Проверка через Context7

Использована официальная документация Qt for Python и документация QtAwesome.

### PySide6 / Qt for Python

Context7 library ID:

- `/websites/doc_qt_io_qtforpython-6`

Из официальной документации подтверждены следующие варианты:

1. `QMovie` может проигрывать анимированные изображения, например GIF, внутри `QLabel`:

   ```python
   movie = QMovie("path/to/animation.gif")
   label.setMovie(movie)
   movie.start()
   ```

   Анимацию можно остановить через `movie.stop()`.

2. `QTimer` может периодически испускать сигнал `timeout()`. Его можно использовать для обновления кадра или угла вращения.

3. Для собственного виджета можно переопределить `paintEvent()`, рисовать через `QPainter`, менять состояние и вызывать `update()` по таймеру.

Источники:

- https://doc.qt.io/qtforpython-6/PySide6/QtGui/QMovie.html
- https://doc.qt.io/qtforpython-6/PySide6/QtCore/QTimer.html
- https://doc.qt.io/qtforpython-6/examples/example_widgetbinding_widgetbinding.html

### QtAwesome

Context7 library ID:

- `/spyder-ide/qtawesome`

Документация QtAwesome подтверждает встроенные анимации:

```python
animation = qta.Spin(widget)
icon = qta.icon("fa5s.spinner", color="red", animation=animation)
widget.setIcon(icon)
animation.stop()
```

Также поддерживается явное управление:

- `animation.start()`;
- `animation.stop()`.

Источники:

- https://github.com/spyder-ide/qtawesome/blob/master/docs/source/usage.md
- https://github.com/spyder-ide/qtawesome/blob/master/README.md

В проекте уже есть зависимость `QtAwesome==1.4.2`, поэтому добавление новой библиотеки не требуется.

## Возможные варианты реализации

### Вариант 1 — QtAwesome `qta.Spin`

Рекомендуемый вариант.

Суть:

- создать один объект анимации, привязанный к статусной иконке;
- создать иконку `fa5s.spinner` с параметром `animation=...`;
- устанавливать эту иконку на статусный widget/label при `busy=True`;
- запускать анимацию при входе в рабочее состояние;
- останавливать её при `Ready`, ошибке, ожидании approval или пользовательского выбора.

Преимущества:

- используется уже установленный QtAwesome;
- не нужны GIF-файлы и новые ресурсы;
- сохраняется текущий визуальный стиль Font Awesome;
- не требуется менять события и payload статусов;
- есть явные `start()` и `stop()`;
- минимальная зона изменений — статусный менеджер и, вероятно, способ отображения иконки.

Ограничение:

- документация QtAwesome демонстрирует анимацию прежде всего через `QPushButton` или `IconWidget`;
- текущий основной элемент — `QLabel`, поэтому нужно проверить совместимость анимированного `QIcon` с конкретным способом отображения в QLabel. Если QLabel получает только `QPixmap`, анимация потеряется.

Практический вывод: для полной надёжности следует использовать `qtawesome.IconWidget` вместо QLabel для иконки либо небольшой собственный widget-адаптер, который принимает анимированный `QIcon`.

### Вариант 2 — отдельный `QMovie` с GIF

Суть:

- добавить GIF-анимацию спинера;
- назначить `QMovie` на `QLabel`;
- запускать и останавливать movie вместе со статусом.

Преимущества:

- официально поддерживается `QLabel`;
- простая модель запуска и остановки;
- не зависит от API анимаций QtAwesome.

Недостатки:

- потребуется новый ресурс GIF;
- сложнее поддерживать цвет, размер, прозрачность и масштабирование в соответствии с текущей темой;
- возможны отличия качества на дисплеях с высоким DPI;
- появляется отдельный визуальный ресурс, дублирующий уже доступную иконку Font Awesome.

Вариант пригоден, если QtAwesome-анимация окажется несовместимой с текущей схемой `QLabel` или потребуется полностью кастомный дизайн спинера.

### Вариант 3 — собственный QWidget с `QPainter` и `QTimer`

Суть:

- создать небольшой widget размером примерно 14x14;
- хранить текущий угол или номер кадра;
- по `QTimer` обновлять состояние;
- в `paintEvent()` рисовать вращающуюся дугу/точки через `QPainter`.

Преимущества:

- полный контроль над дизайном, скоростью, цветом и DPI;
- отсутствие GIF и зависимости от особенностей QtAwesome;
- легко обеспечить корректное поведение в темах проекта.

Недостатки:

- больше собственного кода;
- нужно отдельно проверять корректность перерисовки, размеры и сглаживание;
- для такой небольшой задачи это более существенная реализация, чем требуется сейчас.

Этот вариант оправдан, если нужен уникальный спинер или если готовые варианты не дают нужного качества.

## Рекомендуемый дизайн поведения

Анимация должна быть активна только при реально рабочем статусе:

- `Working...` — вращение включено;
- `Thinking...` — вращение включено;
- статусы инструментов и другие рабочие узлы — вращение включено;
- `Waiting for approval` — вращение остановлено, потому что приложение ждёт действия пользователя;
- `Waiting for your choice` — вращение остановлено по той же причине;
- `Ready` — вращение остановлено, показывается check-circle;
- `Run failed` — вращение остановлено, показывается times-circle.

Это соответствует существующей логике: `busy` уже передаётся в `set_status_visual()` и является достаточным признаком для управления анимацией.

Важно не запускать новый таймер при каждом обновлении текста статуса. При переходе между `Working...` и `Thinking...` нужно переиспользовать одну анимацию и менять только подпись/состояние, иначе можно получить несколько параллельных таймеров или потерю ссылок на animation object.

## Оценка необходимых изменений

Если будет выбран вариант QtAwesome `Spin`, вероятная область изменений:

1. `ui/window_components/menu_builder.py`
   - заменить или дополнить QLabel, используемый как `status_icon`, на widget, способный отображать анимированный QtAwesome icon;
   - сохранить существующее имя ссылки `status_icon`, если это не ограничивает реализацию.

2. `ui/window_components/status_bar_manager.py`
   - хранить объект анимации как атрибут менеджера или статусного widget;
   - создать animated spinner один раз;
   - запускать/останавливать его в `set_status_visual()`;
   - для нерабочих состояний устанавливать статичные иконки.

3. Тесты UI
   - проверить, что busy-состояние запускает анимацию;
   - проверить, что `Ready` и ошибка останавливают анимацию;
   - проверить, что переход между рабочими статусами не создаёт новый объект анимации каждый раз.

Не требуется менять:

- payload события `status_changed`;
- текстовые статусы `Working...`, `Thinking...` и другие;
- backend/runtime-логику;
- зависимости проекта;
- конфигурацию провайдеров.

## Риски и проверки перед реализацией

1. Совместимость QtAwesome animation API с PySide6 6.11.1 и установленным QtAwesome 1.4.2.
2. Возможность отображать animated `QIcon` в выбранном widget без преобразования в статичный `QPixmap`.
3. Корректное уничтожение или остановка анимации при закрытии окна.
4. Поведение при повторном вызове `set_status_visual()` с тем же `busy`-состоянием.
5. Отсутствие мерцания при смене цвета иконки.
6. Работа при выключенном/отсутствующем GUI-тестовом окружении.
7. Масштабирование 14x14 на Windows и мониторах с высоким DPI.
8. Доступность: анимация не должна быть единственным способом определить статус; текст статуса уже остаётся видимым.

## Вывод

Задача реализуема и не требует архитектурных изменений.

Рекомендуется начать с QtAwesome `qta.Spin`, потому что:

- QtAwesome уже используется проектом;
- зависимость уже зафиксирована в `requirements.txt`;
- текущая иконка уже берётся из Font Awesome;
- существующий флаг `busy` естественно управляет `start()`/`stop()`;
- можно сохранить текущие статусы и их обработку.

Главное техническое изменение — не преобразовывать animated icon в `QPixmap`. Если текущий `QLabel` не сможет отображать анимированный QtAwesome icon напрямую, его следует заменить только для области иконки на `qtawesome.IconWidget` или компактный QWidget-адаптер.

Рекомендация из анализа реализована: статусная иконка переведена на `qta.IconWidget` с `qta.Spin`, а запуск и остановка анимации привязаны к флагу `busy`. Добавлена UI-регрессионная проверка. Этот Markdown-файл сохранён как описание решения и его ограничений.
